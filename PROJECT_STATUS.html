What to upload

One file. Not a zip.

Kaggle offers a zip/gz/7z option for agents split across several files. This agent isn’t one — it imports only math and os, so there is nothing to bundle.

kaggle competitions submit -c kaggriculture -f main.py \

  • ✓ Loaded as a file path rather than an imported module it scores $77,114 over 8 games, matching the module numbers.

Do not break this

Kaggle execs the file just to grab agent, so never define a function or class below agent in main.py — it would silently become the submitted agent. A bare if __name__ == "__main__": block is safe (and dead on Kaggle); a def main(): under it is not.

Nothing else gets uploaded. bench.py, tune.py, trace.py, actions.py, baselines/ and the docs are local tooling.

For how the code actually works — every .py file explained and the turn logic step by step — see CODE_GUIDE.pdf (13 pages, source CODE_GUIDE.html). This page is status; that one is understanding.

Quote the self-play number, not the $78k

$78,475 is a benchmark, not a forecast. Against an opponent that genuinely competes for the shared market the score falls 44%, to about $44k. Every other row is against an opponent that barely sells, so our agent alone drains the town’s demand and collects every scarcity premium. Do not report $78k as an expected leaderboard result.

The winrate is meaningless for self-play: the agent is deterministic, so against a copy of itself it plays a mirror match and finishes on identical dollars. About two-thirds of seeds tie exactly, and bench.py scores a tie as a non-win — which is why it prints 3/16 = 19%.

OPP_SUPPLY=1.0 — the contested-market fix

Every row above is measured with OPP_SUPPLY=0. crop_profit priced a harvest against minv − town_drawdown + pipeline, and pipeline holds only our own crop — the opponent’s fields are not in the observation. Both valuation sites now scale it by 1 + OPP_SUPPLY, shipped at 1.0 (assume a symmetric opponent). 0.0 reproduces the old agent exactly, verified to the dollar.

Replicate before you believe a sweep

0.25 led run 1 at 81% and went negative on fresh seeds. Reading the winner off a single sweep would have shipped a no-op. 1.0 is the only value best in both runs — and it is the a-priori correct answer against a mirror, which suggests mechanism rather than curve fit.

Past 2.0 it falls off a cliff: at 3.0 every crop prices as doomed, the agent stops planting, and it loses 0/128 — with the lowest stdev in the table, because it fails uniformly rather than wildly.

This is a trade, not a strict improvement

Flat vs pass (+$118), but it costs $4,761 against v12: assuming a symmetric opponent over-corrects against a weak supplier. It still wins 100% of v12 games, just by less. The right call against a board of live agents; the wrong one against a passive field.

Runtime is 4.6 ms/turn against a 1000 ms actTimeout — there is a great deal of compute headroom left.

This session

Two decisions, both measured

Mid-day porter runs shipped · +$2,202

Units now walk produce to the shed mid-day once the day’s haul is outgrowing it, not only on day 29. Goods reach the shed only at end of day, and anything past the 100-item cap is discarded silently — so ferrying early, where the SELL orders can drain it, recovers output that was being thrown away.

Goose / egg engine built · switched off

Fully implemented — BUILD_COOP, BUY_ANIMAL, PICKUP at the shed, PLACE, then daily FEED/CARE/HARVEST/COLLECT_FERTILIZER, plus a wheat feed reserve and BUY_PRODUCT top-ups. It sits behind MAX_GEESE, which now defaults to 0, because it loses money at every size measured.

The previous handoff called this “the largest single remaining lever” and costed it per tile. But tiles are not the binding constraint — unit-actions are. A bird grosses ~$150/day (2 eggs at ~$42, 1 fertilizer at ~$70, less a $35 wheat) yet needs ~7 actions/day to collect it, and actions.py shows 51.7% of every unit-action is already just walking. Traces showed it managing to feed only 7–11 of 16 birds on a given day.

GOOSE_UPKEEP double-charging crew capacity was tested as the alternative explanation and ruled out (−112, noise).

Engine facts established

All verified against kaggriculture.py rather than inferred from games — worth keeping whatever happens to the flock.

  • BUILD_COOP is free; the $300 is the bird. Requires a None tile.
  • Animals produce whether or not they are fed. Feeding governs survival — two consecutive dry nights and the bird escapes, structure intact — and lets a fed night spend the CARE bonus.
  • FEED draws wheat from the unit’s own inventory, not the shed, so every feed cycle needs a PICKUP run first. This is what makes it so action-hungry.
  • max_held caps only uncollected product, so lifetime output is unbounded.
  • FERTILIZER is in no shop’s list and is excluded from TOWN_CENTER_PRODUCTS — its inventory only moves when we sell, making it a one-shot ~$25k prize that floors after ~495 units, exactly like melon.
  • BUY_ANIMAL lands the bird in the shed, against the 100-item cap.

uv run python main.py prints nothing — that is correct

main.py is the agent module, not a program. It defines constants and functions and exits; nothing calls agent() unless a harness does. Silence and exit code 0 mean the file is healthy. Use trace.py to actually watch it farm.

Two things that save hours

KAG_DEBUG=1 disables the try/except in agent, so exceptions surface instead of silently degrading to PASS. Always develop with it — without it, a crashing agent just looks like a bad score.

KAG_DEBUG=1 uv run bench.py --opp pass -n 4 --workers 4

Tune against pass, never random. The built-in random_agent calls random.Random() with no seed, adding ~3.5% run-to-run noise that drowns real effects.

Every tunable is an environment variable

Still open

What’s pending

  1. 01

    Cut the walking

    51.7% of unit-actions are moves; another 11.5% are PASS. Assignment is greedy per-turn with no notion of a route, so units criss-cross the farm. Biggest remaining lever on the crop engine — and the precondition for the flock ever paying.

  2. 02

    The panic-dump rule is mispriced defect

    When shed_fill + incoming > SHED_CAP − 10, reserve_frac drops to 0.05 and the agent sells anything at almost any price. Flock traces showed it dumping melon at $4 against a $250 base. Overflow really is discarded so the rule is right in principle, but it should dump the cheapest items, not everything. Fires without geese too, whenever crop throughput is high.

  3. 03

    Land timing

    Quadrants 3 and 4 still land around day 11 because cash is tied up in melon seeds until the day-10 harvest. Reserving toward the next land price is probably worth several thousand.

  4. 04

    Re-derive the animal question

    ANIMALS contains only GOOSE — there is no cow or sheep path at all. The comment at main.py:80 rules them out because milk caps at ~$6k lifetime revenue and wool at ~$8k, but that was computed assuming the whole market is ours. Live replays show opponents buying cows on day 1. A capped $6k nobody contests can beat an uncapped wheat plan that several agents are collapsing at once.

  5. 05

    Housekeeping

    The submitted agent is the pre-OPP_SUPPLY build. It scored 636.2 (rank 2197) on 2026-08-11 and drifted to 607.9 (rank 2340) five hours later — though the whole board fell over that window and the rating band was 509–716, so the move is inside the noise. The OPP_SUPPLY=1.0 build has not been submitted. Separately, debug_wrapper.py is redundant with actions.py and can be dropped whenever.
